How it works

The idea

Contract review starts with finding the right sentences: what must be paid, who must do what, how things end, what stays secret. This demo runs those questions over a small corpus and shows the evidence for every hit — the exact sentence, in the exact document.

Query semantics

  • Keyword — case-insensitive substring match over sentences (the name_contains idea: say what you're looking for, plainly).
  • Document type — NDA, MSA, SOW, Contractor, Grant, Vendor.
  • Clause detectors — deterministic patterns, no ML, no black box:
    • Payment terms: dollar amounts, payment, invoice, payable, fee
    • Obligations: shall, must, agrees to, is required to
    • Termination: terminat*
    • Confidentiality: confidential, non-disclosure, NDA
  • Empty query matches nothing — by design. A query with no filters is not a finding.

Discipline

The engine behind this demo was built with a simple rule: a keyword hit is a lead, not a qualification. Every result carries its evidence so a human can review it. Nothing here decides anything on its own.

The corpus

Six short synthetic sample contracts, written for this demo: NDA, Master Services Agreement, Statement of Work, Independent Contractor Agreement, Grant Agreement, Vendor Agreement. They are fictional. They are not templates and not legal advice.

Stack

Static HTML + CSS + JavaScript. No backend, no tracking, no build step, $0 to host. The query engine is a JavaScript port of an open research prototype (doc_queries.py: explicit filters, evidence-carrying results).

Possible next steps

  • Swap the synthetic corpus for real public-domain agreements.
  • Add an open-model layer (e.g. legal-BERT) that maps natural language to the fixed, validated filter set — the model never generates queries freely.
  • Publish an evaluation: precision/recall of each detector on a labeled set.
